# Lab5：5×5 图像卷积性能优化（C 语言多文件编译）

## 1. 实验目标

在保持计算结果正确的前提下，优化一个单线程 C11 图像卷积程序。通过实验理解循环开销、指令级并行、分支、自动向量化和缓存局部性对性能的影响，并掌握多文件程序的编译与测试方法。

本实验不要求复现题面中的某个固定加速比。性能只在同一台机器、同一编译器和相同测试条件下进行相对比较。

## 2. 运算定义

输入图像 `src` 和输出图像 `dst` 均为 `n × n` 的单精度浮点矩阵，采用行优先连续存储。卷积核 `kernel` 固定为 `5 × 5`，同样采用行优先存储。

为避免“数学卷积是否翻转卷积核”的歧义，本实验明确采用深度学习框架中常称为卷积的二维互相关形式：**不翻转卷积核**。

对任意 `0 <= i,j < n`：

```text
dst[i,j] = sum(ki=0..4, kj=0..4)
             sample(i + ki - 2, j + kj - 2) * kernel[ki,kj]
```

其中：

```text
sample(r,c) = src[r,c]，当 0 <= r,c < n
sample(r,c) = 0，其他情况（Zero Padding）
```

因此输出尺寸仍为 `n × n`。累加顺序可以因优化而改变，结果按第 5 节给出的浮点容差判定。

## 3. 编程任务与接口

只优化 `convolution.c` 中的下列函数，不得修改函数名或参数类型：

```c
void convolution(int n,
                 const float *restrict src,
                 const float *restrict kernel,
                 float *restrict dst);
```

调用约束如下：

- `n >= 1`；
- `src` 和 `dst` 各包含至少 `n*n` 个 `float`；
- `kernel` 包含至少 25 个 `float`；
- 三块存储区域互不重叠；
- 函数必须写入全部 `n*n` 个输出元素；
- 不得修改 `src` 或 `kernel`，不得写出 `dst` 的边界；
- 正式评测为单线程评测，不得使用 OpenMP、线程库、GPU 或外部数值计算库；
- 不得针对测试随机种子、特定输入值或计时程序返回预计算结果。

动态内存分配是允许的，但在 `convolution` 函数内部发生的分配、初始化、复制和释放都会计入运行时间。不得用跨调用的可变全局缓存规避计时。

## 5. 正确性判定

参考实现按第 2 节公式计算。对每个输出元素，学生结果必须是有限浮点数，并满足：

```text
abs(student - reference) <= 1e-5 + 1e-5 * abs(reference)
```

公开测试覆盖小于卷积核的图像、边界像素、非对称卷积核、单位卷积核和随机输入。正式评测还会使用未公开的尺寸、卷积核和随机种子，并使用内存检查工具检测越界和未定义行为。

## 7. 性能指标

正式规模为：

```text
N in {512, 1024, 2048, 4096, 8192}
```

对每个规模，处理单个输出像素的平均时间为：

```text
TPE = convolution 总运行时间 / (rounds * N^2)
```

该规模的加速比为：

```text
Speedup(N) = TPE_baseline(N) / TPE_student(N)
```

总加速比采用五个规模加速比的几何平均：

```text
OverallSpeedup = exp(average(log(Speedup(N))))
```

驱动会交替执行参考版本和学生版本，降低固定执行顺序带来的温度及缓存偏差。计时仍会受到系统负载影响，报告中应记录多轮结果，不能只挑选最快的一次。

只有通过正确性检查的程序才统计性能。示例输出中的具体时间和加速比不是评分门槛，不同机器上的数值不要求一致。

## 8. 优化方向

以下方向仅作提示，实际效果必须通过测量验证：

1. 将不依赖内层循环的索引、偏移量和 kernel 值移出热点循环。
2. temp：展开固定的 5×5 计算，减少循环控制和地址计算。
3. ✅使用局部累加器，或使用多个独立累加器增加指令级并行。注意这可能改变浮点加法顺序。
4. ✅将无边界分支的内部区域与少量边界像素分开处理，或者比较显式 padding 的复制成本。
5. 同时计算相邻输出列，改善数据重用并帮助编译器自动向量化。
6. 查看编译器的向量化报告或汇编，确认预期优化是否真正发生。

缓存优化不能只凭概念判断。以常见的 32 KiB L1 数据缓存为例，`N=1024` 时一行 `float` 图像约为 4 KiB，5 行工作集约为 20 KiB；它并非“一行都放不进 L1”。而对每个元素只写一次的矩阵赋值，分块通常不会产生额外数据重用。是否分块以及块大小应由本卷积的实际工作集和测量结果决定。
